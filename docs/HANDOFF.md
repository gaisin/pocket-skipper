# Хендофф: «Карманный шкипер»

Дата: 2026-09-19.
Состояние: всё сделанное опубликовано, ветки `main` и `feature/pocket-skipper` указывают на один коммит `cad928e`.

## Зачем проект

Пользователь - шкипер с сертификатом IYT Bareboat Skipper и УКВ-сертификатом, не ходил 4 года.
В начале октября 2026 у него неделя бербоут-чартера из Фетхие (Турция, район Фетхие - Гёчек) на однокорпусной Dufour 430 Grand Large.
Приложение нужно, чтобы за три недели освежить знания и пользоваться им на воде как шпаргалкой, в том числе без интернета.
Главное требование - проверяемость: у каждого факта есть источник, иначе запись не проходит проверку.

## Устройство

- Статический сайт в `site/`: HTML, CSS и ES-модули, без фреймворка и без сборки.
- Содержание: `site/content/*.json` - `questions`, `situations`, `maneuvers`, `checklists`, `vhf`, `reference`, `guides`, `external`.
- Схема и проверка содержания: `scripts/lib/validate-content.mjs`, запуск `npm run check`.
  Проверка падает без источников, при повторе id, при неверном числе правильных ответов и т.д.
  Она предупреждает, если верный ответ слишком часто самый длинный (порог 40%).
- Офлайн: service worker `site/sw.js`, список файлов генерирует `npm run assets`, версию кеша подставляет CI.
- Прогресс: `localStorage`, повторения по Лейтнеру (5 коробок, интервалы 0, 1, 2, 4, 7 дней), экспорт и импорт в настройках.
- Отметки в карточках ситуаций истекают через 12 часов, чтобы после тренировки настоящая авария не открылась с зачёркнутыми шагами.
- Схемы: свои SVG (`site/js/diagrams/`) - огни, знаки IALA, расхождение судов, сцены манёвров.
  Лодка рисуется носом вверх, `rot` по часовой, `boom` плюс - гик на левом борту, `wind` - откуда дует (0 - сверху), сцена 260×200.
- Тесты: `npm test` (82 модульных, `node:test`), `npm run e2e` (34 теста Playwright в эмуляции iPhone на Chromium).
- Деплой: GitHub Actions `.github/workflows/deploy.yml` при пуше в `main` (check, unit, e2e, затем Pages).

## Правила работы с содержанием

- Каждый факт - из источника, который реально открыт; из памяти не писать.
  Пересказ своими словами, репозиторий публичный: текст и картинки учебника не копировать.
- Номер страницы учебника - печатный: печатная страница = номер PDF-страницы минус 1.
- Ловушка: `awk '!seen[$0]++'` при чтении текста удаляет и законные повторы коротких строк внутри страницы (так потерялось слово «шторм» у 11 баллов Бофорта).
  Перед записью факта перепроверять место без удаления дублей.
- Если учебник устарел, брать действующую норму и записывать расхождение в журнал: реанимация - ERC 2025, отмена ложного DSC-сигнала - МСЭ Res. 349, после принятого DSC-сигнала - IMO MSC.1/Circ.1657.
- Турецкие правила и чартерная специфика - только из веб-источников с датой обращения.
- `verified: true` ставится только вместе со строкой в журнале сверки.
- Русский текст, обычный дефис вместо длинного тире; в длинных Markdown-файлах каждое предложение с новой строки.

## Процесс, который себя оправдал

- Исполнитель на задачу, затем ревью, затем раунды исправлений и повторное ревью.
  Для содержания - старшая модель и у исполнителя, и у ревьюера: ревью регулярно находило реальные ошибки (устаревшая процедура отмены сигнала бедствия, фордевинд на схеме возврата к человеку, неверная трактовка залога, пропущенное «имея ход относительно воды»).
- Параллельные агенты - только в отдельных git worktree; журнал сверки при слиянии конфликтует (оба дописывают в конец таблицы) - оставлять строки обеих сторон.
- Проверка в браузере без интерактивного Chrome: `chrome-headless-shell` из кеша Playwright, управление через DevTools Protocol из временного Node-скрипта.
  Полный Chrome for Testing на этой машине зависает.
- Лимит API обрывал агентов несколько раз; их нужно возобновлять с места остановки, сначала проверив `git status`.

## Технические особенности окружения

- Коммиты от личного аккаунта: имя и почта прописаны только в локальном конфиге репозитория; глобальный конфиг рабочий, его не трогать.
- Строки Co-Authored-By в коммиты не добавлять (требование пользователя).
- Пуш: `GIT_SSH_COMMAND=ssh git push origin main` - глобальный `core.sshCommand` использует рабочий ключ.
- Публикация: работа идёт в `feature/pocket-skipper`, после ревью - `git checkout main && git merge --ff-only feature/pocket-skipper`, пуш, возврат на ветку.
- Ничего не устанавливать без отдельного явного разрешения пользователя (уже разрешены и стоят `@playwright/test` в проекте и `chromium_headless_shell` в кеше Playwright).
- Симулятор iOS недоступен, пока пользователь не выполнит `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.
- В `.claude/worktrees/` остались четыре worktree агентов с ветками `worktree-agent-*`; их изменения уже слиты в основную ветку, worktree и ветки можно удалить.

## Открытые вопросы и непроверенное

- Признание IYT по турецкому регламенту о частных судах (действует с 17.07.2026, RG 17.01.2026 № 33140) не подтверждено ни одним открытым источником.
  Бербоут разрешён арендатору с удостоверением ADB в пределах лимита длины; иностранный документ может быть признан на основе взаимности (ст. 15).
  Пользователю рекомендовано получить письменный ответ базы; в чек-листе это пункт `iyt-new-rules`.
- Резидент ли пользователь ЕС - от этого зависит, какие страховки залога ему доступны (Pantaenius и основной продукт Schomacker - только ЕС; продукт Schomacker для не-ЕС не продают гражданам США, Канады, России и Украины).
- Меню внизу на коротких страницах в режиме приложения на iPhone: исправлено по описанию бага WebKit (`black-translucent`), но не воспроизведено и не проверено на устройстве.
  Если зазор останется и на длинных страницах, запасной вариант - `apple-mobile-web-app-status-bar-style: black` (нужна переустановка ярлыка).
- Статус платных буёв DERİA на октябрь 2026 не известен (суд приостанавливал проект, новый иск готовится).
- Отложенное пользователем: быстрая ссылка MAYDAY уже сделана; других отложенных функций нет.

## Следующая задача: швартовки и отшвартовки

Цель: проработать швартовку и отход разными бортами и кормой при разном ветре, с соседними яхтами и без, со всеми правилами и советами - куда смотреть, как поворачивать, что делает экипаж.

Что уже есть и что не дублировать: манёвры `med-mooring` (кормой на лейзи-линию), `leave-berth` (отход от стоянки кормой), `buoy-pickup`; ситуации и справки по Фетхие; видео Sailing Time (уроки 6, 8, 25, 26 - швартовка и отход).

Предлагаемый объём (согласовать с пользователем перед работой):
- Швартовка кормой (средиземноморская) при ветре с кормы, в нос, боковом слева и справа; с соседями и в пустой причал; с лейзи-линией и со своим якорем.
- Отход от стоянки кормой при тех же ветрах; очередность отдачи концов; как не намотать лейзи-линию.
- Швартовка лагом левым и правым бортом: ветер прижимной, отжимной, вдоль причала спереди и сзади; работа шпрингами; подход под углом и «заброс» кормы.
- Отход лагом: отжимной ветер, прижимной ветер (выход на носовом или кормовом шпринге), с соседом спереди или сзади.
- Заход в тесный ряд между яхтами, разворот в узком проходе марины.
- Эффект винта (заброс кормы на заднем ходу): в какую сторону у этой яхты, как использовать при подходе левым и правым бортом.
- Куда смотреть рулевому, как держать ход (минимальный управляемый), когда давать короткие импульсы, как ставить руль на заднем ходу, двойной штурвал - откуда видно корму и нос.
- Роли и команды экипажа: кто на носу, кто на корме, кранцы, сигналы руками, что говорить.
- Типичные ошибки и как из них выходить (сносит на соседа, не попали концом, лейзи-линия у винта, ветер усилился на подходе - уйти на второй круг).

Факты о яхте, которые нужно проверить по руководству владельца Dufour 430 GL (ссылка есть в источниках манёвров) и у базы, а не предполагать:
- направление вращения винта и тип привода (вал или колонка) - от этого зависит заброс кормы;
- есть ли подруливающее устройство;
- расположение уток, стопоров и кранцев;
- два штурвала (подтверждено), осадка 2,10 м (подтверждено), штатный самоповоротный стаксель (подтверждено).

Источники: учебник IYT (модуль 2 секция 7 «Управление на двигателе» с. 53, модуль 14 секция 5 «Управление судном» с. 217, модуль 9), RYA (Day Skipper, Powerboat/Yacht handling), Yachting Monthly, PBO, Sail Ionian, Safe Skipper, руководство Dufour; видео Sailing Time - только как дополнительный просмотр, не источник.

Форма в приложении (предложение): новые записи в `maneuvers.json` со схемами по шагам (элементы сцены `quay`, `boat-moored`, `line`, `label`, видимость по шагам через `steps`), поле `videos` где уместно, 10-15 вопросов в теме `anchor-mooring`, при необходимости справка-шпаргалка «Швартовка: решения по ветру» в `guides.json`.
Схемы проверять на физику: ветер и снос, куда уходит корма на заднем ходу, не пересекается ли лодка с соседями и причалом.
Как и раньше: исполнитель на старшей модели, затем ревью содержания и схем по скриншотам всех шагов, затем повторное ревью, и только потом публикация.
