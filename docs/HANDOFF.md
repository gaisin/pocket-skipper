# Хендофф: «Карманный шкипер»

Дата: 2026-09-19.
Состояние: работа «Швартовки и отходы» и исправления итогового ревью сделаны в `feature/pocket-skipper`, но не опубликованы.

## Зачем проект

Пользователь - шкипер с сертификатом IYT Bareboat Skipper и УКВ-сертификатом, не ходил 4 года.
В начале октября 2026 у него неделя бербоут-чартера из Фетхие (Турция, район Фетхие - Гёчек) на однокорпусной Dufour 430 Grand Large.
Приложение нужно, чтобы за три недели освежить знания и пользоваться им на воде как шпаргалкой, в том числе без интернета.
Главное требование - проверяемость: у каждого факта есть источник, иначе запись не проходит проверку.

## Устройство

- Статический сайт в `site/`: HTML, CSS и ES-модули, без фреймворка и без сборки.
- Содержание: `site/content/*.json` - `questions`, `situations`, `maneuvers`, `checklists`, `vhf`, `reference`, `guides`, `external`.
- Схема и проверка содержания: `scripts/lib/validate-content.mjs`, запуск `npm run check`.
  Проверка падает без источников, при повторе id, при неверном числе правильных ответов, при нарушении формата зеркального манёвра и т.д.
  Она предупреждает, если верный ответ слишком часто самый длинный (порог 40%).
- Офлайн: service worker `site/sw.js`, список файлов генерирует `npm run assets`, версию кеша подставляет CI.
- Прогресс: `localStorage`, повторения по Лейтнеру (5 коробок, интервалы 0, 1, 2, 4, 7 дней), экспорт и импорт в настройках.
- Отметки в карточках ситуаций истекают через 12 часов, чтобы после тренировки настоящая авария не открылась с зачёркнутыми шагами.
- Схемы: свои SVG (`site/js/diagrams/`) - огни, знаки IALA, расхождение судов, сцены манёвров.
  Лодка рисуется носом вверх, `rot` по часовой, `boom` плюс - гик на левом борту, `wind` - откуда дует (0 - сверху), сцена 260×200 (ширина - `SCENE_WIDTH` в `mirror.js`).
- Тесты: `npm test` (105 модульных, `node:test`), `npm run e2e` (43 теста Playwright в эмуляции iPhone на Chromium).
- Деплой: GitHub Actions `.github/workflows/deploy.yml` при пуше в `main` (check, unit, e2e, затем Pages).

### Сторона заброса и зеркальные манёвры

- Настройка `settings.propWalk`: `left` или `right`, нет ключа - «не проверено».
  Выбирается переключателем «Влево / Вправо» на каждом зеркальном манёвре или полем в настройках; значение общее, проходит через `sanitizeSettings` и потому едет в экспорт и импорт прогресса.
- Базовые схема и текст нарисованы для заброса влево.
  При «вправо» `maneuverFor` (`site/js/diagrams/mirror.js`) отражает схему по ширине сцены и подставляет вторые варианты пар; исходный манёвр не меняется.
- Пока сторона не выбрана, показана схема «влево» и заметка «Сторона не проверена» со ссылкой на манёвр «Проверка заброса кормы и инерции» (`prop-walk-test`); на нём самом ссылки нет.
- Смена стороны сохраняет текущий шаг, перерисовывает схему без анимации и меняет заголовок экрана и вкладки.
- Формат зеркального манёвра: `mirror: true`; пары `[[вариант для «влево»|вариант для «вправо»]]` только в `title`, `summary`, `scene.label`, тексте подписей, `who`, `command` и `text` шагов.
- Проверка содержания для зеркального манёвра: пары только правильной формы; слово о стороне вне пары - ошибка (корни «лев»/«прав» в начале слова, в том числе «влево», «справа», «налево», и «часовой»; «правило», «управление», «направление», «рулевой», «справка», «часов» не считаются); `path` только из абсолютных `M L Q C Z`.
- Элементы сцены, добавленные для швартовок: `arrow` (`x1, y1, x2, y2`, `kind`: `walk` - заброс кормы, красная; `drift` - снос ветром, синяя пунктирная; необязательное `steps`) и `label.anchor` (`start` или `end`; при отражении меняется местами, подпись без `anchor` получает `end`).
  Под схемой - легенда только тех видов стрелок, что есть в манёвре.
- В отражённой сцене стрелка ветра стоит справа сверху (подпись «ВЕТЕР» слева от неё) - подписи туда не ставить.

## Что проверить на приёмке яхты

По руководству Dufour 430 GL этого не установить, в приложении это сформулировано как проверки (чек-лист «Приёмка яхты», справка «Швартовка и отход», манёвр «Проверка заброса кормы и инерции»):
- в какую сторону и насколько сильно уводит корму на заднем ходу - потом выбрать сторону в приложении (переключатель на манёвре или настройки);
- стоит ли складной винт (в руководстве он упомянут, с. 21);
- у какого штурвала рычаг газа и приборы двигателя (по схеме с. 82-83 сторону не определить);
- есть ли подруливающее устройство (на Dufour 430 GL это опция);
- какая версия киля: глубокий (осадка 2,10 м) или мелкий (1,75 м).

## Правила работы с содержанием

- Каждый факт - из источника, который реально открыт; из памяти не писать.
  Пересказ своими словами, репозиторий публичный: текст и картинки учебника и руководства Dufour не копировать.
- Номер страницы учебника - печатный: печатная страница = номер PDF-страницы минус 1.
- Ловушка: `awk '!seen[$0]++'` при чтении текста удаляет и законные повторы коротких строк внутри страницы (так потерялось слово «шторм» у 11 баллов Бофорта).
  Перед записью факта перепроверять место без удаления дублей.
- Если учебник устарел, брать действующую норму и записывать расхождение в журнал: реанимация - ERC 2025, отмена ложного DSC-сигнала - МСЭ Res. 349, после принятого DSC-сигнала - IMO MSC.1/Circ.1657.
- Турецкие правила и чартерная специфика - только из веб-источников с датой обращения.
- Про эту яхту - по руководству Dufour 430 GL; чего в нём нет (сторона заброса, газ, подруливающее), писать как проверку, а не как факт.
- Привод у яхты - saildrive, вала нет: советы «про вал» из общих источников не переносить.
- Видео Sailing Time - только в поле `videos`, не источник.
- `verified: true` ставится только вместе со строкой в журнале сверки.
- Русский текст, обычный дефис вместо длинного тире; в длинных Markdown-файлах каждое предложение с новой строки.

## Инструменты

- `npm run shots -- <id ...> [--out папка]` - PNG каждого шага манёвра (по умолчанию в `.local/shots`, без id - все манёвры); для зеркального - обе стороны: `<id>-left-01.png`, `<id>-right-01.png`...
  Нужен запущенный `npm run serve`.
- `PORT` - один и тот же для `npm run serve`, `npm run shots` и `npm run e2e` (по умолчанию 4173); параллельным worktree и агентам - разные порты.
  Playwright при `PORT` заново использует уже запущенный на нём сервер.
- Страница руководства Dufour в PNG: `osascript -l JavaScript .local/dufour/render-page.js <pdf> <папка> <номер...>` - схемы (палуба, двигатель) сверять по изображению, в тексте их нет.
- Проверка в браузере без интерактивного Chrome: только headless (`chromium.launch()` из Playwright или `chrome-headless-shell` из кеша Playwright через DevTools Protocol).
  Полный Chrome for Testing на этой машине зависает.

## Процесс, который себя оправдал

- Исполнитель на задачу, затем ревью, затем раунды исправлений и повторное ревью; в конце - итоговое ревью всей ветки.

- Параллельные агенты - только в отдельных git worktree; журнал сверки при слиянии конфликтует (оба дописывают в конец таблицы) - оставлять строки обеих сторон.
- Агентские worktree создаются от `main`, а не от рабочей ветки: первым шагом агента - fast-forward на `feature/pocket-skipper`, и проверить это по `git worktree list`.
- Параллельным агентам - разные `PORT`, иначе они тихо тестируют чужой сайт.
- Лимит API обрывал агентов несколько раз; их нужно возобновлять с места остановки, сначала проверив `git status`.

## Технические особенности окружения

- Коммиты от личного аккаунта: имя и почта прописаны только в локальном конфиге репозитория; глобальный конфиг рабочий, его не трогать.
- Строки Co-Authored-By в коммиты не добавлять (требование пользователя).
- Пуш: `GIT_SSH_COMMAND=ssh git push origin main` - глобальный `core.sshCommand` использует рабочий ключ.
- Публикация: работа идёт в `feature/pocket-skipper`, после ревью и «да» пользователя - `git checkout main && git merge --ff-only feature/pocket-skipper`, пуш, возврат на ветку.
- Ничего не устанавливать без отдельного явного разрешения пользователя (уже разрешены и стоят `@playwright/test` в проекте и `chromium_headless_shell` в кеше Playwright).
- Симулятор iOS недоступен, пока пользователь не выполнит `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.
- Уборка после публикации: в `.claude/worktrees/` три worktree агентов (`agent-a0bdb77cfd80fa310`, `agent-a7a70208239006df8`, `agent-a84ab2189d31a8551`) с ветками `worktree-agent-*`; их изменения слиты в `feature/pocket-skipper`, после публикации worktree и ветки можно удалить (`git worktree remove`, `git branch -d`).

## Открытые вопросы и непроверенное

- Признание IYT по турецкому регламенту о частных судах (действует с 17.07.2026, RG 17.01.2026 № 33140) не подтверждено ни одним открытым источником.
