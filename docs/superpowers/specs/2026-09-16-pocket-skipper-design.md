# Карманный шкипер - дизайн

Дата: 2026-09-16.
Статус: черновик на согласование.

## Цель

Офлайн-приложение для iPhone, которое за три недели освежает знания шкипера IYT Bareboat Skipper перед недельным чартером.
Поездка: Турция, выход из Фетхие, однокорпусная Dufour 430, ориентировочно начало октября 2026.
Главное требование к содержанию - проверяемость: у каждого факта есть ссылка на первоисточник.

## Нецели

- Не замена учебнику, официальному тексту МППСС и местным правилам.
- Нет аккаунтов, сервера, синхронизации между устройствами.
- Нет навигации по картам и работы с живыми данными (погода, AIS).

## Платформа

- PWA: статический сайт, устанавливается на экран «Домой» в iOS Safari и работает без сети.
- Хостинг: GitHub Pages, публичный репозиторий `gaisin/pocket-skipper`, адрес `https://gaisin.github.io/pocket-skipper/`.
- Коммиты - от личного аккаунта `gaisin` с почтой `27743952+gaisin@users.noreply.github.com`, прописанной только в локальном конфиге репозитория.
- Стек: HTML, CSS и JavaScript (ES-модули) без фреймворка и без шага сборки.
  Причина: маленький объём, долгий срок жизни без обновления зависимостей, GitHub Pages отдаёт файлы как есть.
- Шрифты (Oswald, Onest, JetBrains Mono, лицензия OFL) лежат в репозитории, чтобы работать офлайн.
- Service worker кеширует все файлы при первом открытии; версия кеша меняется при каждом деплое; при появлении сети приложение показывает «Доступна новая версия - обновить».
- Прогресс хранится в `localStorage`; в настройках есть экспорт и импорт прогресса в JSON-файл на случай очистки данных iOS.

## Визуальный стиль

Берётся из `first_draft.html` без изменений:
палитра navy / sea / port red / starboard green / buoy yellow, светлая и тёмная темы, шрифты Oswald (заголовки и команды), Onest (текст), JetBrains Mono (метки, источники).
Все схемы - собственные SVG в стиле демо-схемы оверштага.
Картинки из учебника IYT не копируются.

## Структура приложения

Нижняя панель из пяти вкладок.

### Сегодня

- Ежедневная сессия интервальных повторений по системе Лейтнера: 5 коробок, интервалы 0, 1, 2, 4, 7 дней.
- Сессия - до 15 карточек, примерно 10 минут.
- Счётчик «до выхода N дней» и доля карточек в коробках 4-5 как показатель готовности.
- Карточки для повторения - это вопросы из вкладки «Тесты».

### Тесты

- Темы: расхождение судов, огни и знаки, звуковые сигналы, система IALA регион A, УКВ-радио, метеорология, якорная стоянка, безопасность, приёмка и обязанности шкипера.
- Режимы: тренировка по теме (сразу разбор) и пробный экзамен (случайные вопросы, разбор в конце, порог 70%).
- Типы вопросов: выбор одного ответа, выбор по картинке (ночные огни, знаки, ситуация расхождения на SVG).

### Ситуации

Чек-листы действий с отметкой выполненных шагов.
Первая очередь: человек за бортом, пожар, посадка на мель, намотка на винт, отказ двигателя, усиление ветра и шквал, течь, медицинская помощь, оставление судна.

### Манёвры

Пошаговые SVG-схемы с командами шкипера и действиями экипажа.
Первая очередь: оверштаг, фордевинд, швартовка кормой на муринг (средиземноморская), отход от причала кормой, постановка на якорь и снятие, взятие рифа, возврат к человеку за бортом (quick stop и под мотором), подход к бую.

### Ещё

- **УКВ-радио:** каналы и их назначение, шаблоны Mayday, Pan-Pan, Sécurité с полями для названия и MMSI яхты, фонетический алфавит, DSC-вызов по шагам, типичные вызовы марины.
- **Подготовка к поездке:** чек-лист по неделям до выхода - документы, приложения на телефон, скачать офлайн-карты, одежда и личное, местные правила Турции.
- **Приёмка яхты:** чек-лист приёмки у чартерной компании - документы и инвентарь, корпус и такелаж, двигатель, электрика, безопасность, тузик и мотор.
- **Справочник:** огни, дневные знаки, буи IALA A, шкала Бофорта, звуковые сигналы.
- **Внешние тесты:** ссылки на сторонние онлайн-тесты (открываются при наличии сети).
- **Настройки:** дата выхода, название яхты и MMSI для радиошаблонов, экспорт и импорт прогресса.

Отметки в чек-листах сохраняются, есть кнопка «сбросить список».

## Содержание и защита от ошибок

### Модель данных

Содержание хранится в файлах `site/content/*.json`, по файлу на тип: `questions.json`, `situations.json`, `maneuvers.json`, `checklists.json`, `vhf.json`, `reference.json`.

Каждая запись содержит:

- `id` - стабильный идентификатор (нужен для прогресса);
- `sources` - непустой список источников;
- `verified` - `true`, только когда текст сверен с каждым источником из списка.

Формы источника:

- `{"type": "iyt", "module": 8, "section": 5, "page": 149}` - учебник «IYT BBS rus», номер страницы как напечатан в книге;
- `{"type": "colregs", "rule": 26}` - МППСС-72;
- `{"type": "iala", "topic": "lateral-a"}` - система буев IALA;
- `{"type": "web", "title": "...", "url": "...", "accessed": "2026-09-16"}` - веб-страница.

### Отображение

- Внизу каждой карточки мелким моноширинным шрифтом: список источников, например `IYT BBS, модуль 8, с. 149 · МППСС-72, пр. 26`.
- Несверенная запись помечается жёлтой меткой «не сверено».

### Проверка

- Скрипт `scripts/check-content.mjs` (Node, без зависимостей) падает, если у записи нет источников, если `id` повторяются, если у вопроса нет ровно одного правильного ответа или если в источнике не хватает полей.
- Скрипт запускается локально и в GitHub Actions перед деплоем; при ошибке деплой не выполняется.

### Процесс наполнения

1. Текст учебника извлечён из PDF в локальный файл (в репозиторий не попадает).
2. Каждая запись пишется своими словами по учебнику или официальному тексту, со ссылкой на страницу или правило.
3. `verified: true` ставится только после сверки с цитатой источника.
4. Местная специфика Турции (каналы марин, Mavi Kart, требования к документам) берётся только из найденных веб-источников с датой обращения.
5. Сторонние онлайн-тесты используются для перекрёстной проверки и как ссылки; их вопросы не копируются.

## Тестирование

- Модульные тесты на встроенном `node:test` (без установки пакетов): расписание Лейтнера, проверка контента, экспорт и импорт прогресса.
- E2E-тесты на Playwright в эмуляции iPhone: прохождение теста, отметка чек-листа, шаги манёвра, работа без сети после первой загрузки.
  Пакет `@playwright/test` нужно поставить в проект как dev-зависимость - это будет отдельно согласовано перед установкой.
- Перед сдачей - ручная проверка установки на реальном iPhone.
